# Project Invariants

1. **Preserve Repository & Git History:** Never re-initialize, rewrite, or force-push shared Git history. Preserve existing collaborator configurations and user work.
2. **Separation of Concerns:** Keep `frontend/` and `backend/` strictly separated.
3. **No Premature Application Code:** Do not initialize frameworks (React, Vite, Next.js, Node.js, Python web frameworks, databases, Docker, or deployment tooling) before the official problem statement is announced.
4. **Minimal Dependencies:** Avoid unnecessary dependencies or boilerplate.
5. **Clean Project Structure:** Maintain a clean, predictable directory layout.
6. **Preserve Working Functionality:** Do not break or overwrite existing working features when iterating.
7. **Evidence-Only Reporting:** Never fabricate implementation details, file changes, or test results.
8. **No Secrets in VCS:** Never commit credentials, API keys, tokens, or `.env` files.
9. **Equal Collaborative Access:** Do not assign individual teammate responsibilities, roles, or permanent file ownership. All collaborators may work across the entire repository.
